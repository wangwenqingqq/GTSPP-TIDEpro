# Gate 2：持续读服务的有限普通控制实验

登记日期：2026-09-15；先登记，再开发校准/调参，再冻结测试。Gate 1 源码和证据不改。

## 范围与停止条件

只测 256-bit、约 10M、native Q=8、τ=.8，整卡观测预算 1280/2048 MiB。
沿用 Gate 1 v4 同一 kernel、arena、大 run size class 和单个 8 MiB pinned staging。
不做新机制，不扩到 41M，不追加参数搜索或负载扫描。
没有用户提供的业务 SLO，以下只是技术门槛，不能称为生产达标。

开发集是 splitmix64(ID xor 20260913) % 4 == 1，测试集复用 Gate 1 的余数 0。
两者 ID/查询 ID 不相交，但共享六个历史日期及相似大小模式；测试数据曾在 Gate 1
被观察，不能称为盲测、独立历史或外部查询分布。64 个查询按各自 cohort 生成。

## 固定时间与记账

单 FIFO reader，固定到达序列，不以完成时间生成下一请求。起点在预热后，留 100 ms
线程启动余量。固定读窗口 [0,8000) ms；六次维护到达为 750,1750,…,5750 ms。
writer 顺序执行，前次没完成时后次排队，不丢维护事件。不能预定真实发布时刻；
记录到达、开始、发布和实际回收，实际发布延迟是结果，不能为各策略改变时间轴。
所有已到达请求在窗口后排空，最多额外 8000 ms，超限整个尝试失败并保留证据。
完整输出留在有界 host 结果数组；oracle 检查和 CSV 格式化在读窗口/排空之后。
服务时间含 acquire、GPU、D2H、输出排序和 owner 释放；响应时间从预定到达算到
Runtime 返回后，包含排队与尾部 CUDA event 计时开销。窗口内完成率以全部预定到达
为分母；排空吞吐不能冒充窗口吞吐。请求/维护 backlog 分开记录，不丢请求。

覆盖门槛：六次维护全部在固定窗口内发布，旧 epoch owner 和独占 run 在窗口内
释放（共享 run 不应提前回收；shadow 故意持有的可见 epoch 0/base 除外），growth 的每个 epoch 至少被一个窗口内完成请求
看到；shadow 保持可见 base 不变，仍执行全部六次维护。缺失记 FAIL，不能延长窗口。

## 开发、冻结、测试

每个预算先在开发集最终单 run 静态布局上，预热后连续测 512 个 batch。
固定到达间隔为 ceil(mean 完整返回时间 / .8 / .01) * .01 ms，且不小于 .1 ms。
随后用该间隔跑一次 8 秒开发 static_final；响应 p99 的两倍为该预算技术延迟上限。
窗口内完成率要求 >=99%，发布可见延迟 <=1000 ms，覆盖/完整正确性/内存均须通过。
这只检验一个开发校准负载点，不证明更高负载或不同 Q/τ 也成立。

调参只允许 periodic k={2,3,6}、size-tiered factor={2,4}，每预算每配置一次开发
growth。periodic 每 k 次更新全合并；tiered 相邻前 run <= factor * 后 run 时合并。
按覆盖通过、完成率/发布延迟/响应门槛通过优先，再按响应 p99、上传字节、参数值
排序，各家族各预算选一个。调参只决定配置，不据测试重选。完整开发记录和选择规则
写入冻结文件并 SHA256，必须先于第一个测试进程。即使全失败也保留家族最优作为诊断，
不得隐去失败。all_delta 和每次 compact 是未调参参考。

测试四个 fresh-process 重复，轮换四策略顺序，预算顺序交替。每预算/重复都有
static_base、static_final；四策略各跑 shadow 和 growth。同一预算的每个 arm 使用
同一到达序列和查询顺序（query first=(batch_index*8)%64），共 80 个主测试 case。
静态到 shadow 只解释维护干扰，growth 同时改变可见行数，不能直接全归因维护。
shadow 在受限预算可能因保留可见 base 降低合并数；必须比较 work ledger，工作量
不一致的 shadow/growth 不作等工作量因果对照。

四次测试均满足门槛的普通配置，足以在此范围停止这个候选。否则只报告可重复缺口和
可观测归因，单次异常、基线自身失败或工作量不匹配不作为新算法必要性的证据。
统计重复单位是 fresh process，不把 batch/批内查询当独立实验重复。

## 资源和验证

新独立远端目录，输入/历史证据只读。GPU index/UUID 双核对，沿用 global 和单卡
非阻塞锁；外来进程/预算越界即停止自己的 child，不触碰其他任务。每 child 180 秒，
整 campaign 2400 秒。NVML 0.5 秒采样和运行时 CUDA 边界观测不能证明未采样瞬间。
沿用已验证 GPU runtime；新增协议用 fixture 在普通与 memcheck 下覆盖两种动态模式，
再用完整 oracle 对所有开发/测试输出逐条核对。调参、时钟、覆盖和冻结逻辑做 CPU 测试。
任何实现缺陷修订后保留旧尝试；不能混合版本或仅重跑有利 case。
