# 审稿问题 → 修复证据

此表是重启清单，不是对完成状态的承诺。数据来自用户提供的审稿文档/稿件/历史记录；新增 CPU 参考不代替原代码修复。

| 问题 | 目前证据 | 下一步最低要求 | 不应采用的补救 |
|---|---|---|---|
| 祖先界陈旧导致漏检（R3 D1） | 原稿叶级更新不足以证明可见；Safe-C1 提供保守证书 | 钉住代码提交，true-arrival 每步精确 oracle，边界/gap/叶满/重建前后 | 仅证明路由 O(log n) 或统计插入返回成功 |
| 校准近似与精确性混淆 | gamma>1 只会更激进，不能保证精确 | 精确主线 gamma=1；近似线独立测试漂移和 ground-truth 成本 | 将审稿人“更多剪枝不漏”的误解当正确性背书 |
| 旧收益主要来自 B=10 和内存分配 | R2 400→13→11 分解；R5 incremental | 所有结构比较共享 workspace/batching/合理 buffer 调优 | 把去除明显实现低效再次计成新结构贡献 |
| 泛化只声明未实现 | Safe-TIDE 仅有 GTS host；多指标不等于同一联合多模态索引 | 定义 host 合同和限制；跨 host 主张必须有第二实现 | 同时处理 DNA/化学/视频的虚构需求；声称所有树都适用 |
| HNSW 定位错误 | 原算法论文支持一般度量搜索 | 区分算法能力、软件实际接口、近似/精确语义 | 以“图方法必须坐标”为由排除比较 |
| 真实应用不足 | SureChEMBL 真实版本有基础；计时仍从已准备指纹开始 | raw→FP→diff→publish→query→元数据的实跑与两条时钟 | 给 SIFT-1M 加“视频库”标签 |
| 小规模/分布覆盖不足 | 41M 256-bit 查询有成绩；2048-bit 仅静态正确性 | 先小规模定位，再代表性规模/阈值/分布/连续发布 | 所有维度一起加大，得到无归因大实验 |
| 并发实验混合增长与干扰 | 已有 epoch 精确性；旧 .918 吞吐值混合两种作用 | 同一搜索集合的维护对照 + 实际增长对照分开 | 宣称 .918 单独等于发布干扰 |
| 融合贡献薄 | 真实一次增量 1.010/1.018；人工 64 片 1.591/1.873 | 保留为执行控制；研究真实长历史是否存在新交互 | 继续把 single launch 作为核心新机制 |
| 采样结构不够有效 | 现代模型 rank16 评估捕获 57.7%，界仍很松 | 相同元数据预算下局部证书是否能完成真实判定、计入全部工作 | 以所有 bounds 更紧冒充速度优势 |

此外检查伪代码重建分支是否包含本次触发重建的新对象；原稿文字未清楚表达，属于需要查代码和添加回归的事项，不能仅凭伪代码认定实际二进制一定丢对象。
