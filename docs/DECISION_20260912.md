# GTS++ / TIDE：独立评估与重启决策

日期：2026-09-12。目标：有可辩护贡献的完整研究论文；不承诺录用，不默认降成 demo 或 benchmark。

## 证据边界

本次直接查看了原稿、Safe-TIDE、化学版 TIDE、三份审稿意见、导师图片，并检索了三份研究对话的关键实验及最新检查点。以下旧性能数据来自你提供的稿件或历史记录，**不是本次在 GPU 上重新验证**。原始 CSV、二进制及服务器工作区没有随附件完整迁入，不能把日志中的“通过”当作本次独立复现。

本次新增的是本包 CPU 语义参考及 24 项通过的回归测试。它们说明数学反例和参考接口的行为，不证明原 CUDA 程序已修复。

## 结论

有继续形成论文的机会，但原 GTS++ 的三项优化不能仅靠换名、交换次序、补大规模柱状图就变成新的中心贡献。优先保留 TIDE 精确检索服务的实现和实验，冻结原 GTS++ 未复核主张；精确 Top-p 采样应作为独立课题而非救稿捷径。

已有组件不新，不等于系统贡献一定被覆盖；但已有系统整体已经具备同问题、同保证、同机制与同执行条件时，换到 GPU 或换一个数据集也不构成充分区别。判断要落到具体交互和公平对照，不要求“只有我们能解决”。

## 原 GTS++ 首先需要恢复可验证的正确性

原稿第 8 页 Algorithm 2 对区间外新对象选择最近区间，伪代码只显示叶级覆盖更新。R3 D1 对祖先范围陈旧的质疑成立为一个必须排除的风险。

数学反例：实数轴绝对距离，枢轴 p=0，祖先历史覆盖 [0,1]。把 x=2 放入该子树但不修祖先界。查询 q=2、半径 0.1 时，旧界给出 LB=1，剪掉真实距离为 0 的命中。路由开销为 O(log n) 不能证明后续查询可见性。

Safe-TIDE 的全路径证书 + 精确 delta 是合理的保守修复，但当前稿只实现/声明 GTS 布局，其他 host 仍是接口可能性，不能说已经通用部署。原始“100% 直接插入成功”也不等于 oracle 通过。

历史评估记录报告了真实到达漏检、stride 问题、校准划分与声明不符，以及一个安全版本比 all-delta 慢约 6.5%。这些记录足以要求封存旧性能主张；在没有对应源码和原始运行材料的本轮，不进一步断言所有版本都有这些运行时问题。

C2 中 gamma>1 不是更强的精确下界。“额外剪枝更多”不能推出“不漏结果”。精确主线关闭该近似模块；保留近似实验时，独立声明召回语义、划分和漂移成本。检查实现中的 cosine 究竟是 angular/normalized L2 还是 1-cos；后者不能直接套用度量三角不等式。

## TIDE 已有的正证据应保留

化学版稿件报告：七个 SureChEMBL 快照/六次 insert-only 转移、最新 41,126,808 条记录；3,072 次发布-查询正确性检查；最大转移中的 24,576 个并发更新工作负载请求与其获取的 epoch 一致。稿件第 14–15 页报告并发工作负载保留约 0.918 倍吞吐、p99 比值 1.094。

这些值说明已有一个实质原型，不应被“没有新算子”抹掉。不过吞吐控制搜索 base，更新组多次搜索更大的 union，因此它们混合了数据增长和发布干扰；不是固定数据量的纯干扰归因。

查询性能也有后续有利证据：百万行、256-bit、Q=64 的普通批处理后仍比 nvMolKit 快 4.02–5.04 倍；约 69,632 行的分片 FPSim2Cuda 对照中 p95 差距仍约 14.14–14.24 倍。两者均来自历史记录，规模、batch 与 41M 单查询结果不同，不能混合成一个统一加速比。

## 不能再当作未验证创新的点

chemfp 已提供跨文件分片检索/合并；GPU LSM 与 GPU Multiversion B-Tree 已有动态层次、快照和版本所有权相关先例。TIDE 的候选集等价式是集合恒等式，不是新的定理。

主研究日志后部已经做了公平融合消融：相同 GPU、内核、边界和输出下，base + 一次真实增量的收益为 1.010 / 1.018 倍；把同一增量人工分为 64 片后为 1.591 / 1.873 倍。原稿仍写“未隔离该对照”，说明稿件落后于后续记录。该结果否定“融合单独解释真实单次发布巨大收益”，不否定真实多次发布中更复杂的维护问题。

此外，论文 base+64 保留了超过 99.94% 的完整 base，只切分占总量约 0.050478% 的最新 delta，不能充当 64 次自然发布或全库碎片化实验。

## 两个延伸方向

### A. 不算全部词表 logits，保持全词表 Top-p 分布

问题与近似输出层检索、对已知 logits 的排序消除不同，因此不能用“有 HNSW”或“有 FlashInfer”一句话否决。但原始概率质量界/拒绝采样有广泛先例，局部残差证书尚需机制与成本验证。

最新记录已不是只有 LSTM：SmolLM2-135M、词表 49,152、hidden size 576 的诊断中，普通界总对数松弛约 96.3% 来自几何界；rank-16 捕获校准平方范数 93.9%，评估仅 57.7%；2048 个界都更紧仍不能支持有效直接采样。百分比不是时间占比、不是加速潜力。只有一款小模型、两篇评估文章，还没有采样器和 GPU 端到端成绩。

结论：有依据的独立高风险探索；停止“简单全局低秩球界已经够用”的候选，不判死整个问题。短期救 TIDE 的优先级低。

### B. 边更新边提供精确检索

这是离现有实现、数据、应用最近的路线。小样本上传实验只有约 0.54–0.62 ms 的曝光、覆盖 5–6 个请求，属于证据不足而非“更新干扰不存在”。下一步应该是代表性连续发布与固定数据量干扰分离，不再重复同一小样本。

## 建议研究问题：先作为假设，不提前命名为贡献

在固定显存预算、快照一致和完整结果语义下，持续发布的可剪枝索引，如何在局部物理维护、查询扫描与旧版本持有之间作决策？

一个可检验差异是：相同 run 数和字节数并不一定对应相同实际查询成本；每个 run 的精确可选区间、批量形状、尾块浪费及保留版本内存可能共同决定哪部分维护才值得。需要先验证这些信息是否改变可行决策，而不是只给普通 compaction 多加参数。动态 workload-driven compaction 本身已有 ArceKV 等先例。

建议先拿 7–14 天做一轮封顶试验：普通强控制能否在真实长序列中同时维持发布、查询、显存？失败时先定位是接口/语言开销、普通 batching、run 描述符、扫描、结果生成，还是确实存在结构交互；有证据才设计/实现针对性的维护机制。

继续条件不是固定 3 倍速度，也不是已经满足完整论文。要看到可以复现的成本差异、解释该差异的信息，以及一个可结束的下一步。若普通策略已经足够，停止该候选机制，保留 TIDE 资产和新测量。

## 真实应用

采用 SureChEMBL 原始分子/专利数据驱动的版本化相似分子检索：原始结构 → 固定参数指纹 → 稳定 ID 差分及更新分类 → 验证/发布 → 查询获取 epoch → 完整精确 ID → 回连分子和专利元数据 → 展示新增命中。

同时报告原始数据到应用输出、预计算输入到可见两条时间线。不把下载、指纹生成、delta 排序排除后仍称全链路。真实发布、受控回放、人工压力负载分别标注。指纹精确相似不是活性预测或专利法律结论；不虚构生产 SLA。
