# 下一轮：一次有结束条件的研究验证

**状态：计划，未执行 GPU 实验。** 建议第一轮工作量封顶 7–14 天；无任意 3× 或“必须已经新颖才能观察”门槛。

## 唯一主问题

固定显存、精确阈值检索与每请求固定快照的条件下，真实连续发布是否产生普通分片/调优合并策略无法便宜消除的成本？若有，哪些可观测局部状态解释它？

先诊断现有 TIDE，不同时实现新采样器、另一种树和多 GPU。CPU 参考只用于接口回归，不比较性能。

## 固定合同

指纹参数、输入宽度、稳定 ID、合法阈值、空指纹约定、重复 ID 策略、输出格式、输出溢出处理、epoch 获取时刻、初始快照、每次实际更新均写入 run card。精确性指对指定指纹的整数阈值谓词完整正确，不暗示分子活性/真实语义相似一定正确。

正式时钟分别记录：(1) 原始分子数据至应用结果；(2) 准备好的指纹输入至首个完整新版本结果；(3) 单请求服务延迟；(4) 持续服务吞吐。排队、warmup、oracle、排序、校准各自计时，不能隐匿。

## 已经做过，不重复作为新发现

- 全库和部分条件下的查询性能、六次真实发布、部分并发 epoch 正确性。
- 普通 native batching；百万行 Q=64 的比较。
- 同 kernel 的单发射/逐 run 入队控制。
- 小样本分片 FPSim2Cuda 对照。
- 小样本上传曝光不足，下一轮不能继续复用仅 5–6 个重叠请求的归因结论。

## 第一阶段：固定执行层的普通强控制

统一优化后的 GPU 内核、workspace、批量策略、输出和版本所有权。比较 all-delta/不合并（直到明确预算限制）、固定周期合并、按大小/层级倍增合并，以及完整压实查询参考。参数在开发 trace 上选择，不用最终 test trace 的未来操作比例当先验。

外部 FPSim2Cuda 分片适配与可获得授权的 chemfp 使用相同输入/可见/输出语义。库级接口快慢与同内核结构消融分别报告，不能互相替代。nvMolKit 作为已公开接口的查询上下文；不得让必须生成全矩阵的接口成为“唯一最强阈值搜索基线”。

## 第二阶段：连续真实发布与有标签的压力测试

已有自然版本按时间顺序累计，不要每轮又重置到同一个 base。自然记录不足以到达稳态时，明确只报告有限历史，再增加单列的受控压力负载；不把人工切片说成真实发布次数。

按预算逐步覆盖：N=1M→10M→可容纳的实际全库；256/2048-bit；阈值 0.5/0.7/0.8/0.9（结果过多时仍应完整输出并计成本或明确失败，不截断）；Q=1/8/64；base 查询、未来到达查询、外部 held-out 查询。实际受支持的组合才运行，不能把 2048-bit 静态正确性称作动态性能结果。

分布包括自然 popcount 分布、来源/结构家族分层、热点更新、查询偏移。按明示方式构造的部分标注 synthetic/stress，不宣称生产分布。

## 第三阶段：将增长和维护干扰拆开

采用两组独立实验：

A. 固定一个已发布查询集合，执行与真实维护等量的 shadow 上传/整理，但不改变查询集合，隔离资源干扰。shadow 不作为发布正确性证据。

B. 实际发布增长快照，记录 old/new epoch 的完整结果，分别分析每个 epoch 的服务成本和整个更新时段。

使用真实代表性的较大增量；重复独立发布事件获取足够请求暴露，不人为 sleep 延长上传。若真实负载维护始终轻微，这也是可接受结论。

## 需要采集的解释变量

每请求/per-run 的 exact candidate rows、扫描字节、尾块占比、描述符成本、batch 形状、输出字节；每维护事件的复制字节、构建时间、未回收版本字节、峰值 host/device 内存、等待队列、完成时间。评估是否“同 run 数/同大小却不同查询覆盖”造成真正策略差异。

结构候选的成本估计只能是工作假设：

    总成本 = 实际查询扫描/输出 + 发布准备/传输 + 维护工作 + 版本持有成本

这些项不应机械相加替代并发测量；重叠、带宽争用、排队必须通过实测处理。

## 判定与下一步

支持继续：出现可重现且非普通实现低效导致的差距；差距随可观察的布局/查询/版本因素改变；可以提出明确改变该代价的机制。下一轮才实现一个候选，与强控制同口径比较。

支持停止该候选：普通优化策略已覆盖可行区间；收益主要是 Python/CuPy 接口或每 run 同步；只在极小人工 delta 切片中成立；证书/决策成本吞掉全部收益。停止对象写为具体假设，不是整个 TIDE 方向。

证据不足：资源不足、自然 trace 太短、暴露请求太少、原始证据未迁入。记录缺什么和最小补充，不冒充算法反证。

## 通用性

这轮优先证明化学应用中的问题。只有后续拟提出跨索引维护层时，才选择另一个真正不同的 host（例如修复后的区间度量树），给出可见性/枚举/重建合同和实际适配；不能以潜在接口列表替代第二实现。
